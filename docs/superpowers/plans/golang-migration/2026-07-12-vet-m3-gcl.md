## M3.0 — `internal/gcl` 公共包（🔒 先完成并冻结接口）

### 子包划分（来自 CodeGraph 分析 §1.3）
- `internal/gcl/secret`：凭据遮蔽
  - `MaskSecrets(text string) string`
  - `HasCredentialLeak(text string) bool`
  - `DetectCredentialFields(text string) []string`
  - 来源：`gcl_runner.mask_secrets` / `has_credential_leak` / `detect_credential_fields`
- `internal/gcl/critic`：评分与裁决
  - `StructuralCritic(gen map[string]any) map[string]any`
  - `ValidateCriticPayload(c map[string]any) []string`（返回错误列表）
  - `Decide(scores map[string]float64) string`（返回 PASS/NEEDS_FIX/ABORT）
  - 来源：`structural_critic` / `validate_critic_payload` / `decide`
- `internal/gcl/trace`：trace schema 读写
  - `Trace` struct（对应 Python dict 结构，字段含 scores/operation/trace 等）
  - `Parse(path string) (*Trace, error)`
  - `Persist(root string, t *Trace) (string, error)`
  - `LastScores(t *Trace) map[string]float64`
  - 来源：`gcl_runner.persist_trace` / `gcl_trace_aggregate.parse_trace` / `last_scores`
- `internal/gcl/format`：人类可读格式化
  - `FormatHuman(reports []Report) string`
  - 来源：各 `cmd_*` 的 `_format_human` 模式（统一签名）

### 冻结要求
- M3.0 接口定稿后**不再更改**；M3.1–M3.3 只能依赖已发布签名。
- 须有 `_test.go` 覆盖遮蔽/裁决/解析关键路径（用 fixtures 对拍 Python 行为）。

## M3.1 — `vet gcl run` ← `gcl_runner.py`（🔀 依赖 M3.0）
- Go 包：`cmd/vet/internal/gclrun`
- Python 关键：`run_command`, `load_critic`, `run_isolated_critic`, `extract_failure_pattern`, `load_known_failure_patterns`, `_writeback_failure_pattern`, `derive_operation_intent`, `cmd_run`
- 参数：`--skill`(req)、`--request`(req)、`--command`(req)、`--max-iter`(int,default nil)、`--timeout`(int,default 120)、`--critic-json`(path)、`--critic-stdin`(bool)
- **吸收 `gcl_critic_stub.py`**：`--critic-stdin` 从 stdin 读 critic JSON（stub 行为内联，不再单独暴露子命令）。
- 安全关键：全程经 `secret.MaskSecrets` 处理输出与 trace；trace 中不得出现明文密钥（等价于 Python `mask_secrets`）。
- 测试点：用 `gcl_runner_test.py` 的测试用例（SecretMasking/RunCommand/StructuralCritic/LoadCritic/Decide/PersistTrace 等）转 Go `_test.go` 对拍。
