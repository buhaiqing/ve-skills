# M2 — 校验类迁移（check 组，🔀 7 个子任务可并行）

> **父计划**：`2026-07-12-python-to-go-cli.md`
> **CodeGraph 依据**：10 脚本零互依赖，M2.1–M2.7 之间无耦合 → 可同时开 7 个 worktree 并行开发。
> **依赖**：M1（存在 `cmd/vet/` module 与 `vet check` 路由入口）。
> **公共约定**：每个子任务 = 1 个 Python 文件 → 1 个 Go 包（`cmd/vet/internal/check/<name>`）+ 1 个 `_test.go`。
> 参数统一：`--root`（默认 repo 根，Go 里用 `flag` 默认 `../../` 相对可执行文件，或 `os.Getwd()` 兜底）；`--json` 机器可读输出。

---

## 通用等价判据（每个子任务适用）
- **输入对齐**：`vet check <name> --root <dir>` 对应 `python3 scripts/<file>.py --root <dir>`。
- **输出契约**：
  - human 模式：stdout 文本，结尾换行；全部通过 exit 0，有失败 exit 1。
  - `--json` 模式：stdout 单条 JSON（`{"summary":{...},"reports":[...]}` 或等价结构），exit 码语义同上。
- **对拍方法**：用 `scripts/fixtures/` 样例（若无则自建临时 fixtures），同输入下 Python 输出 vs Go 输出逐字段比对（JSON 模式）；human 模式比对关键行（通过/失败计数、失败 skill 名）。
- **安全**：校验类不含凭据，无需遮蔽；但读文件须防路径穿越（`--root` 之外不读）。

## M2.1 — `vet check frontmatter` ← `validate_skills_frontmatter.py`
- Go 包：`internal/check/frontmatter`
- Python 关键函数：`extract_frontmatter`, `has_key`, `nested_metadata_field`, `top_level_field`, `validate_skill`
- 逻辑：遍历 `ve-*-ops/SKILL.md`，解析 YAML frontmatter，校验必填字段（name/description/license/compatibility/metadata）。
- 测试点：`_test.go` 用内联 fixture SKILL.md 字符串，验证通过/缺失字段两种路径。

## M2.2 — `vet check aiops` ← `check_aiops_coverage.py`
- Go 包：`internal/check/aiops`
- Python 关键函数：`check_skill`
- 逻辑：对每个 skill 检查 `references/advanced/aiops.md` 与 `references/advanced/finops.md` 存在性（security-critical 8 个 skill 须有 securityops.md）。
- 测试点：构造有/无 advanced 文件的 skill 目录 fixture。

## M2.3 — `vet check assessment` ← `validate_product_assessment.py`
- Go 包：`internal/check/assessment`
- Python 关键函数：`extract_example_jsons`, `validate_finding`, `validate_assessment`
- 逻辑：从 markdown 抽取嵌入 JSON，校验 product/pillar/finding 结构。
- 测试点：合法 + 非法 JSON 样例对拍。

## M2.4 — `vet check gcl` ← `check_gcl_conformance.py`
- Go 包：`internal/check/gcl`
- Python 关键函数：`_count_numbered_sections`, `check_skill`, `check_all`, `_format_human`, `cmd_check`
- 参数：`--root`、`--json`（**注意**：此脚本无 `--skills` 参数，仅 root/json）
- 逻辑：校验每个 SKILL.md 的 GCL 结构（rubric 8 节 / prompt 5 节 / `## Quality Gate (GCL)` 存在性）。
- 等价判据 human 输出格式：`GCL conformance: {passing}/{total} skills conform.` + 失败明细（FAIL <skill>: ...）。
- 测试点：用现有 skill 目录对拍计数。

## M2.5 — `vet check links` ← `check_markdown_links.py`
- Go 包：`internal/check/links`
- Python 关键：`Finding`(类), `iter_markdown_files`, `normalize_target`, `resolve_target`, `target_exists`, `check_file`
- 逻辑：遍历所有 `.md`，校验内部链接目标（`[...](path)`）在磁盘存在；支持 repo 相对路径解析。
- 注意：文件系统 I/O 重，Go 用 `filepath.WalkDir`（标准库，高效）。
- 测试点：构造含有效/失效链接的 fixture 目录对拍。

## M2.6 — `vet check eval` ← `check_eval_regression.py`（最复杂，独占 1 Agent）
- Go 包：`internal/check/eval`
- Python 关键：`_tokenize`, `_score_matches`, `_validate_eval_schema`, `_get_changed_skills_by_git`, `_check_delta`, `_check_skill`
- 逻辑：调 `git` 命令（`exec.Command("git", ...)`）取变更 skill，读 `assets/eval_queries.json`，做语义漂移检测（trigger 分类是否随代码变更退化）。
- 参数：`--root`、`--json` + 脚本 440-447 的额外参数（base_rev 等，迁移时从 build_parser 提取）。
- 注意：依赖外部 `git` 命令，Go 用 `os/exec`；测试用 `scripts/fixtures/` + 临时 git repo。
- 测试点：构造变更前后的 eval_queries 对拍 `_check_delta` 输出。

## M2.7 — `vet validate` ← `validate_local.py`
- Go 包：`internal/validate`
- Python 关键：`Step`(类), `_check_file_integrity`, `_check_required_sections`, `_check_error_taxonomy`, `_check_te1_hardcodes`, `build_steps`, `_inline_script`, `run_step`
- **特殊语义**：原脚本动态生成并执行内联 Python 脚本（`_inline_script` 返回 Python 源码，`run_step` 调 `sys.executable` 执行）。Go 版须保留"执行外部命令"语义：
  - 若内联脚本是 Python → Go 用 `exec.Command("python3", "-c", src)` 或写临时文件执行（与原行为一致）。
  - 若未来可纯 Go 实现检查项 → 直接实现，但须保证输出与 Python 版等价。
- 参数：`--root`、`--list`（仅打印步骤不执行）。
- 测试点：用现有 skill 目录对拍各步骤 exit code 与输出。
