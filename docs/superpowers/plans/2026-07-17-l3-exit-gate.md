## 0. Scope

Close the two remaining partial L3 DoD items:

- **P5 (full-chain observability):** the runtime `vet gcl run` persists `gcl-trace-*.json` (schema `trace_schema_version`/`skill`/`operation_intent`; per-iteration `generator`/`decision`/`policy_decision`) that currently emits **no `request_id`** — it never parses `ve`'s `{"Response":{"RequestId":"..."}}`. Fix: (a) collect `RequestId` at runtime into each `Iteration.request_id`; (b) validate runtime traces via a **new** `gcl/trace.Check`; (c) `vet check trace` must scan `gcl-trace-*` + `incident-trace-*`.
- **P7 (safety-regression guard):** wire the already-existing `vet check policyguard` into CI so "Safety=0 → never AUTO/executed" is enforced on every push/PR.

**Out of scope:** L4 features (T09–T16); any change to `scoreDecision` / `policyguard` invariants; `--confirmed-by` (shipped in `9d9e03c`). The existing `check/trace.Check` (incident schema) is **not** modified.

## 1. Milestones

### M1 — Collect RequestId at runtime (`cmd/vet/internal/gcl/run/run.go` + `cmd/vet/internal/gcl/trace/trace.go`)
**Files:** `cmd/vet/internal/gcl/trace/trace.go`, `cmd/vet/internal/gcl/run/run.go`

- Add `RequestID string` to `trace.Iteration` (`json:"request_id,omitempty"`).
- In `Run()`, after `runCommand`, parse `Response.RequestId` from the (masked) generator output and store it on the `Iteration.RequestID` built at L531.
  - On the first iteration the gate may block before any `ve` call ran → `RequestID` stays empty (expected, valid — see M2 skip rule).
  - Parser: tolerant JSON extraction of `Response.RequestId` from the combined stdout/stderr; blank if absent.

### M2 — Runtime-trace validation (`cmd/vet/internal/gcl/trace/trace.go`)
**File:** `cmd/vet/internal/gcl/trace/trace.go`

- Add `Check(path string) error`:
  - Parse file; if `trace_schema_version == ""` → return nil (not a runtime trace; leave to `check/trace.Check`).
  - Validate `redaction_pass == true`.
  - For each iteration where `generator.command != ""` AND `decision != "POLICY_BLOCK"`: require `iterations[].request_id` non-empty; else error `iterations[%d].request_id is required`.
- Keep `CollectPaths`/`PersistTrace` unchanged.

### M3 — Scan both trace shapes in `vet check trace` (`cmd/vet/check.go`)
**File:** `cmd/vet/cmd/vet/check.go` `traceCheck`

- Remove the `incident-trace-` only filter.
- For each `*.json` in `audit-results/`:
  - if name starts with `gcl-trace-` → run `gcl/trace.Check` (runtime schema).
  - if name starts with `incident-trace-` → run `check/trace.Check` (incident schema, unchanged).
  - else skip.
- Count failures across both; exit 1 if any.

### M4 — Add runtime-trace regression tests (`cmd/vet/internal/gcl/trace/trace_test.go`)
**File:** `cmd/vet/internal/gcl/trace/trace_test.go`

- `TestCheck_RuntimeMissingRequestID`: write a runtime-shape `gcl-trace-*.json` with an iteration that ran a command but has empty `request_id` → assert `Check` errors mentioning `request_id`.
- `TestCheck_RuntimeValid`: runtime-shape trace with `request_id` populated + `redaction_pass` → passes.
- `TestCheck_RuntimePolicyBlockSkipsRequestID`: a `POLICY_BLOCK` iteration with empty `request_id` → does NOT fail (no `ve` call ran).

### M5 — Wire CI (`.github/workflows/validate.yml`)
**File:** `.github/workflows/validate.yml`

- After `vet gcl gate --skip-incident-loop`, add:
  - `vet check trace --root .` (P5)
  - `vet check policyguard --root .` (P7)
- (Steps already added in `validate.yml` during a prior attempt; verify they are present and consistent.)

### M6 — Mark L3 DoD (`docs/l2-to-l3-plan.md`)
**File:** `docs/l2-to-l3-plan.md`

- §6 L3 DoD: P5 ✅, P7 ✅ (set after `go test ./...` + local CI simulation green).
