# KMS Core Concepts

## Overview

Volcengine KMS (Key Management Service, 密钥管理服务) is a managed service that makes it easy to create and control encryption keys used to encrypt your data. KMS uses hardware security modules (HSMs) to protect the security of your keys.

## Key Concepts

### Customer Master Key (CMK)

A Customer Master Key (CMK) is a logical key that represents the top-level key resource in KMS. CMKs can be:

- **Symmetric (AES)**: Used for encryption/decryption
- **Asymmetric (RSA/SM2)**: Used for encryption/decryption or signing/verification

### Key Specs

| Spec | Algorithm | Usage | Description |
|------|-----------|-------|-------------|
| `AES_256` | AES-256-GCM | Symmetric encryption | 256-bit AES key (recommended) |
| `AES_128` | AES-128-GCM | Symmetric encryption | 128-bit AES key |
| `RSA_2048` | RSA | Asymmetric encrypt/decrypt or sign/verify | 2048-bit RSA key |
| `RSA_3072` | RSA | Asymmetric encrypt/decrypt or sign/verify | 3072-bit RSA key |
| `RSA_4096` | RSA | Asymmetric encrypt/decrypt or sign/verify | 4096-bit RSA key |
| `SM2` | SM2 | Asymmetric sign/verify | Chinese national standard algorithm |

### Key Usage

| Usage | Operations | Description |
|-------|------------|-------------|
| `ENCRYPT_DECRYPT` | Encrypt, Decrypt, GenerateDataKey | Encryption and decryption operations |
| `SIGN_VERIFY` | Sign, Verify | Digital signature operations |

### Key States

```
[Create] → Enabled ←→ Disabled
              ↓
       PendingDeletion ←→ [Cancel] → Disabled
              ↓
         [Deleted after waiting period]
```

| State | Description | Allowed Operations |
|-------|-------------|-------------------|
| `Enabled` | Key is active and usable | All operations |
| `Disabled` | Key is disabled but not deleted | EnableKey, DescribeKey, ScheduleKeyDeletion |
| `PendingDeletion` | Key scheduled for deletion | CancelKeyDeletion, DescribeKey |
| `PendingImport` | External key pending material import | ImportKeyMaterial, DeleteKeyMaterial |

### Key Origin

| Origin | Description |
|--------|-------------|
| `VOLCENGINE_KMS` | Key material generated by Volcengine KMS |
| `EXTERNAL` | Key material imported by customer |

## Encryption Concepts

### Encryption Context

Encryption context is a set of key-value pairs that you can pass to KMS encryption operations. The same encryption context must be provided for decryption.

**Benefits:**
- Additional authenticated data (integrity verification)
- Policy condition support (restrict decryption based on context)
- CloudTrail log filtering

**Example:**
```json
{
  "Purpose": "ApplicationData",
  "Environment": "Production",
  "ApplicationId": "app-12345"
}
```

### Data Keys

Data keys are encryption keys that you can use to encrypt data outside of KMS. Best practice:

1. Generate a data key using `GenerateDataKey`
2. Use the **plaintext** data key to encrypt your data locally
3. Store the **encrypted** data key alongside your encrypted data
4. Discard the plaintext key from memory
5. To decrypt, call `Decrypt` on the encrypted data key

### Envelope Encryption

KMS uses envelope encryption to protect data:

```
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│  Your Data      │────▶│  Data Key (DEK) │────▶│  CMK (KEK)      │
│  (Encrypted)    │     │  (Encrypted)    │     │  (AWS managed)  │
└─────────────────┘     └─────────────────┘     └─────────────────┘
```

- **DEK (Data Encryption Key)**: Encrypts your actual data
- **KEK (Key Encryption Key)**: Your CMK, encrypts the DEK

## Key Rotation

### Automatic Rotation

- Supported for symmetric keys with `VOLCENGINE_KMS` origin
- Default period: 365 days
- Rotated keys maintain backward compatibility
- Old ciphertexts can still be decrypted

### Manual Rotation

- Create new key
- Re-encrypt data with new key
- Schedule old key deletion

## Access Control

### Key Policies

Key policies control access to CMKs. Every CMK has a default policy that:
- Allows the account root full access
- Can be customized to restrict access

### Grants

Grants provide temporary, scoped permissions:
- **Grantee Principal**: Who receives the permission
- **Retiring Principal**: Who can revoke the grant
- **Operations**: Specific KMS operations allowed
- **Constraints**: Optional encryption context constraints

## Quotas and Limits

| Resource | Default Limit |
|----------|--------------|
| CMKs per region | 200 |
| Grants per CMK | 250 |
| Key aliases | 100 |
| Pending deletion waiting period | 7-30 days |
| API rate limits | Varies by operation |

## Security Best Practices

1. **Use encryption context** for all encryption operations
2. **Enable automatic rotation** for long-lived keys
3. **Use data keys** for application-level encryption
4. **Monitor key usage** via CloudTrail
5. **Restrict key policies** to least privilege
6. **Use grants** for temporary access
7. **Never delete keys** that protect production data without backup
